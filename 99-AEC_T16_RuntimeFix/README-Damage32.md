# 联机高额伤害修复（1.27.9 / Damage32 V1）

修复加入房间后单次伤害超过 65,535 时，红色飘字高于房主实际收到的伤害的问题。

## 安装

房主（或专用服务器）和所有玩家都需要更新同一份 `99-AEC_T16_RuntimeFix` DLL，并完全退出、重启游戏。XML 热重载不能更新 DLL。当前目录已安装新版；给其他人的更新包内保留了 `99-AEC_T16_RuntimeFix` 文件夹层级，合并到各自的 `Mods` 目录即可。不要删除原模组的 Config、资源或其他文件。

不同协议版本、缺少补丁或补丁未成功启用时，会拒绝联机并提示更新。旧客户端如果先被游戏自带的网络包类型检查拒绝，可能显示原版“模组/网络包不匹配”提示。单机不需要其他机器配合。不改存档格式。

## 实现

- 普通伤害继续发送原版 `NetPackageDamageEntity`。
- 超过 65,535 时返回派生包 `NetPackagePZAECFullDamageV1`：保留原版完整载荷，末尾追加 Int32 完整伤害（4 字节）。包名中的 V1 是协议版本；原版包格式不变。
- 只替换 `NetPackageDamageEntity.ProcessPackage` 内重建 `DamageResponse.Strength` 的读取指令，其余原生命中事件、扣血、击杀及转发流程保留。房主转发时也经过包选择入口。
- 不拆成多次命中，不额外扣血，不重新套用爆头倍率、伤害加成或护甲计算。
- 登录版本字符串附加能力标记，服务器验证；客户端同时验证服务器映射表中的 V1 包名。游戏本身的兼容版本字段不变。
- 无效、非高额、截断的扩展载荷拒绝读取；重复使用接收对象时清除残留完整伤害和武器引用。

Int32 是传输数值范围，不代表游戏内所有伤害计算都能安全达到该上限。Boss 回血、无敌、其他模组干预及同步延迟仍按原有逻辑运行。

## 验证

`pwsh -NoProfile -File tools/Test-HighDamageNetworking.ps1`

离线测试读取实际游戏 IL，执行原版载荷序列化和伤害响应重建，覆盖 0、1、65,534、65,535、65,536、20 万、100 万、Int32 上限、两次收发、连续 1,000 发和交替攻击者、致死标记、异常数据及协议匹配。离线执行省略网络包 ID 头和 Unity 世界，不能代替真实双端联机测试。

联机验收：两端日志都应出现 `[AEC-Damage32] V1 active`。先在无回血、无额外伤害效果的高血量目标上，分别测试低于上限和约 20 万伤害的单发，再测试连续爆头，核对房主端血量差。最后验证击杀、经验、掉落、任务计数，以及第三位观察者的血条显示。

回退必须所有参与者一起回退到相同旧版 DLL；存档无需转换。
