# 凤凰血月终章0.1.3修复包

## 修复

修复血月结束时实体名称哈希为负数导致 `Missing phoenix entity class` 并停用整场会话的问题。改为查询原生实体注册表并核对注册名称，合法负数ID可以生成；真正缺失或名称不匹配时输出名称和ID。

构建脚本显式包含当前运行实现，排除未被0.1.2 DLL使用且引用已删除字段的旧命中框原型。战斗、八段命中框、火球、模型资源、血月门槛及防重复存档顺序不变。

## 验证

- 使用本机游戏／Mono程序集编译0.1.3成功。
- `Test-EntityLookup.ps1`直接测试修复DLL、原生 `EntityClass.FromString` 与原生注册表，22项离线检查通过，包括负ID、正ID、四档名称、缺失定义、空值、名称不匹配，以及编译后终章确实调用修复方法并保持先记录后生成。
- 本次测试的T17 ID为负数，查找成功。离线宿主的哈希具体数值不代表游戏Mono运行时的数值。
- 隔离原生QA的终章模拟参与者从T16改为T17，四档工厂验证前均经过新的注册表校验；该QA插件本轮只编译，没有启动游戏执行。
- 未进行实际血月或真实双客户端验收；未向正式存档生成凤凰、删除记录或回拨时间。

## 更新方式

完整包位于 `.local-tests/Phoenix-0.1.3/PhoenixBoss-0.1.3.zip`，压缩包顶层为 `95-PhoenixBoss`。

正常退出游戏和服务器后，备份原 `Mods/95-PhoenixBoss`，把修复包中的同名目录完整覆盖进去。房主／服务器必须更新；客户端也使用同版本。日志来源机器安装在E盘，当前修复工作区在F盘，本包需要复制到实际使用的游戏安装目录。

启动后日志应出现 `[PhoenixBoss] 0.1.3 T16-T19 blood moon finale loaded; registry-based entity lookup.`。默认从后续正常血月验证；已经错过的血月不会保证自动补刷，是否仍在重试窗口取决于存档时间和 `phoenix-bloodmoon.xml`，不要直接删除该文件。

打包时本机游戏仍在运行，先保留了完整待装包。随后确认游戏及服务器进程均已退出，已备份旧DLL、ModInfo和README并安装本机0.1.3；安装目录全部11个文件与发布包逐文件SHA256一致。下次启动生效，E盘日志来源机器仍需自行更新。
