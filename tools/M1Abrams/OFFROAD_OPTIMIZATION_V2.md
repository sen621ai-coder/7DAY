# M1 越野与越障优化方案 V2

日期：2026-09-29。状态：待实施设计；本文件不修改运行代码、模型或配置。

实施更新：主要底盘优化现已落地至 0.4.6，受控动态对照见 [OFFROAD_0.4.6_VALIDATION.md](OFFROAD_0.4.6_VALIDATION.md)。以下保留原始设计目标；未执行的客户端/网络及扩展场景检查，不因原生受控测试通过而自动视为通过。

基线为当前 0.4.5 的 M1Model、M1Chassis、M1ChassisRules。本文数值都是游戏内调校起点或验收目标，不是已测性能，也不是现实 M1 参数。此前 OFFROAD_DESIGN.md 中被撤销的完整地形系统不因此恢复实施。

## 目标与范围

让 M1 在路沿、碎石起伏、缓坡和浅沟上比普通四驱卡车更可靠，保留重型车辆的体积、速度和转向代价。优先让现有 0.60 米台阶能力稳定，再考虑提高极限。

四阶共用碰撞轮廓、悬挂方案和越障高度；以 T16 完成基础验收，T17–T19 保留已有动力区别，不增加阶级专属爬墙能力。武器、装甲、材料、燃油基础规则、公路极速和低耐久限速保持现状。优先保持四个原生驱动轮，不引入 14 点虚拟支撑、地表陷车或复杂涉水系统。

## 已确认的实现与问题

| 当前实现 | 对越障的影响 |
|---|---|
| 四轮位于 X=±1.36、Z=±2.15，半径 0.40 米，悬挂 0.28 米 | 履带中段接触地形时可能只有车体碰撞，没有驱动轮牵引 |
| 下车体腹部最低模型 Y=0.285，连续履带最低 Y=0.035 | 这些是局部坐标，须测带载站姿后才能判断实际离地间隙；不能直接当作地面间隙 |
| 上车体另有 3.45×0.54×7.2 米盒体 | 验证整个碰撞包络，不能只优化下壳而忽略上壳先碰障碍 |
| 前方三通道要求近似平齐且正对的台阶 | 斜入、小高差和不规则石块容易被全部拒绝 |
| 每步重新寻找台阶正面，任一次失效就结束尝试 | 车头越过边沿后，原台阶可能不再可见，辅助可能在车尾上台前退出 |
| 尝试最多 2 秒，0.6 秒无进展即停止，退后 0.5 米重试 | 缺少完成状态和连续障碍的重新识别；慢速长车身通过可能超过时间窗口 |
| 驱动轮真实接地点才有附加牵引 | 连续履带碰撞解决了穿入问题，没有完整解决中段牵引问题 |

## 第一阶段：越障过程连续，优先交付

### 1. 建立接近、攀入、车腹通过、驶离四个阶段

接近时确认障碍高度、台面、顶部空间及左右落脚面，记录当前障碍的局部几何描述与世界原点偏移信息。每个物理步复查当前位置的真实接触和可用空间；记录障碍不能替代实时支撑。

前轮进入台面后切换到攀入/车腹通过判定，不再要求原来的正面探测射线仍能命中台阶。后轮越过障碍、车腹脱离边沿且姿态开始稳定后判为完成，正常完成允许识别下一处障碍。受阻失败才保留退后重试要求。世界原点移动、瞬移或物理所有者切换时清空缓存。

停滞检测从“每次累计 3 厘米”改为滑动窗口沿行进方向的净进展，初始窗口 0.8 秒、最小进展 3 厘米；总时限按前后支点通过距离和低速进展估算，限定 3–6 秒。高度变化只能作为阶段判定，不能单独重置停滞计时，防止顶墙摇摆不断续期。

几何探测短暂漏检允许最多 0.15 秒重新识别，此间不继续按旧探测增加辅助。失去有效承重、刹车、缺油、入水、离座、所有权变化必须立即停止施力，不经过宽限。

### 2. 分开处理左右履带的障碍

左右通道分别检测高度与平台，中央通道只负责车腹和上方净空，不再要求中央与两条履带同高。以 15° 斜入为首期验收目标，30° 为探索用例；降低接近速度及辅助输出随角度增加而下降。

左右高差允许值先从 0.12 米逐步试到 0.20 米，须同时满足实际侧倾和支撑稳定性要求，不能仅靠高差阈值批准攀越。单侧完全悬空、支撑退化为不稳定窄线时不提供额外抬头。需要转向修正时平滑减弱牵引与姿态辅助，避免越障和原地转向同时满输出。

台阶高度目标仍为 0.60 米。连续上升台阶需重新验证当前障碍和落脚空间，不能把一次通过结果复用于整面墙。

### 3. 改善失败后的倒退退出

增加低速倒车探测，采用后方实际碰撞轮廓和落脚条件，初始辅助限速 4 km/h、障碍高度上限 0.30 米、牵引上限为前进辅助的 60%。姿态力矩跟随行进方向，退后只提供接地牵引，不强行抬起腹部。

如果后方没有可用地面或车辆已完全托底，停止辅助。正常驾驶输入即可触发，不增加专用越野按键。

## 第二阶段：改善真实接触下的牵引

### 4. 履带中段真实接触牵引原型

优先使用左右连续履带碰撞体与静态地形/方块的真实碰撞接触。接触必须位于履带有效底缘或前后斜面，法线具有足够向上分量，并能构成稳定承重。墙面、炮塔、上壳、车腹、其他车辆、角色、触发器不作为牵引点。

仅当前物理所有者在有效碰撞持续期间沿接触面施加切向力。轮接触辅助与履带接触辅助共用单个总预算，初始维持当前 0.8 m/s² 附加加速度上限；只有实测牵引不足且无弹跳后，才探索至 1.2 m/s²。不得随接触点数量增加总输出。

Unity 碰撞冲量不能未经验证就当作每个接触点的独立静态载荷。先记录轮载荷、碰撞冲量、接触分布，验证可用的承重估计，再分配预算；墙体冲击峰值不能转化为持续牵引。无法可靠估计时保持保守总限幅，不伪造接触载荷。

抬头辅助也与这些真实支撑联动，不能继续仅依赖旧的四轮接地开关，否则中段牵引不会解决原问题。支撑消失当步停止施力；不增加虚拟支撑、向上托举或位置改写。

此项作为可独立关闭的原型，先在孤立测试场验证。若接触数据不稳定，保留第一阶段收益，暂缓该项；新增驱动轮要另行核实原生 VehicleWheel、刹车、总扭矩分配和网络生命周期，不直接插入额外 WheelCollider。

### 5. 悬挂与碰撞调校

先测静止压缩量、车腹实际间隙、履带贴地偏差，再比较悬挂 0.28、0.32、0.36 米三个档位。质量保持 12,000；安装高度、弹簧和阻尼要配套调节，不能仅拉长行程。选最小可达标档位，要求平地不趴地、不长期悬浮，起伏后不持续振荡。

保留连续履带实体碰撞和车腹防穿透。按模型轮廓检查前后过渡、上壳盒体与障碍接触顺序，仅在碰撞体明显超出可见外形或形成不必要尖角时修正。不得用大幅缩短车体、抬空整个履带或删除腹部碰撞获得通过率。

### 6. 低速坡地控制

平缓坡优先依赖原生驱动；仅在低速、有有效承重且持续给油时补充有限切向牵引，与台阶辅助共用预算，不能叠加两套满额输出。驾驶员松油门后退出攀爬，刹车拥有最高优先级。

先验收 15°、25°硬地连续坡和坡上起步；30°作为目标，35°、45°只做边界记录。下坡测试制动距离和侧滑，必要时补充有限发动机制动，不锁定位置或速度。侧倾增大时降低转向辅助，保留当前受支撑条件约束的摇摆阻尼。

## 验收场景与指标

以下是拟定通过标准，需动态行驶验证，静态碰撞重叠或策略单元测试不能替代。

| 场景 | 操作与目标 |
|---|---|
| 0.15/0.30 米路沿 | 低速 5–8 km/h 正入，每种 10 次均能通过；无明显弹射或持续托底 |
| 0.45/0.60 米宽台阶 | 3–6 km/h 正入，各至少 9/10 次通过；0.60 米台面纵深至少 2 米并记录实际尺寸 |
| 0.30/0.45 米斜入台阶 | 15°斜入各至少 9/10 次；30°单独记录，不算首批硬性指标 |
| 0.30 米倒车障碍 | 2–4 km/h，至少 9/10 次通过；失败后可松油门停车 |
| 连续两处台阶 | 前后有足够停车/支撑平台，验证成功完成后可识别下一处，不必须倒退重新武装 |
| 宽缓凸起、窄横梁、腹部独石 | 区分履带承重与车腹托底；能走的持续牵引，不能走的可停止尝试，无无限摇摆 |
| 15°/25°硬坡 | 连续坡及坡上停车再起步各 10/10 次；30°记录目标差距 |
| 10°/15°侧坡 | ≤6 km/h 横行并小幅转向，记录侧滑/翻覆；不强制锁定姿态 |
| 0.8/1.2 米横沟 | 3–6 km/h 正入，各至少 9/10 次，记录沟深、边缘形状；悬空阶段无辅助支撑 |
| 1.5 米沟、0.75/0.90 米台阶 | 探索能力边界，不作为首版承诺；不以提升辅助阈值强行达标 |
| 1 米直墙、顶上有障碍、无落脚面 | 拒绝攀爬；持续给油 20 秒及反复点按均不能累积升高 |
| 缺油、刹车、入水、离座、单侧悬空 | 对应退出条件当步停止主动辅助，无缓存继续施力 |
| 公路启停、急转、坡上开炮 | 公路极速不变；制动距离及稳定性对照基线，排除辅助与后坐力相互放大 |

每组重置相同出生位置、姿态、完整耐久、燃油、改装状态、控制输入和障碍，分别跑原 M1、优化 M1、普通四驱卡车。先比较无模组 T16 与无改装卡车，再回归四阶及动力模组、低耐久状态。记录通过率、通过耗时、最高俯仰/侧倾、托底时长、前进净距离及是否发生弹射。卡车对比用于实测评价，不预设所有项目必须获胜。

动态遥测包括实际接触来源/数量、轮载荷、碰撞冲量、总辅助力和力矩、尝试阶段/退出原因、速度、车腹接触及物理所有者。诊断输出限频，关闭时不逐帧分配；记录单车和多辆同时行驶时的物理帧开销。

联机覆盖单人、主机驾驶、客户端驾驶、专服驾驶、换驾驶员、收起重放、保存重载及 100–200ms 延迟。每辆车仅一个物理所有者施力；旁观端不能重复辅助或出现持续位置回弹。检测缓冲溢出保守退出，缓存只保存瞬态信息。

## 实施顺序与交付

1. 建立可重复的动态测试路线和遥测，留存 0.4.5 对照 DLL/配置及成绩。
2. 实现第一阶段：越障阶段、完成/失败区分、斜入和倒退；运行策略测试、原生动态测试与联机退出回归。
3. 在独立开关下加入中段真实接触牵引；验证共用力预算后，再调悬挂、碰撞和坡地控制，每次只改变一组变量。
4. 将达到的高度/坡度/沟宽写入 README，只发布实测成绩；未达目标保留为限制。源码变化时更新版本、重建 DLL，并保留可回退产物。

涉及文件：M1ChassisRules.cs（阶段及策略）、M1Chassis.cs（探测/接触/施力）、M1Model.cs（悬挂/碰撞）、Test-Chassis.ps1 与 NativeQA.cs（规则和动态验证）。必要的测试场与遥测单独放在 tools/M1Abrams，避免把测试逻辑带入正常玩家流程。
