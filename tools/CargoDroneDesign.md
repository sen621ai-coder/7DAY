# 搬运无人机：玩法与技术设计

日期：2026-09-21。阶段：设计提案，尚未编写或安装运行代码。以下数值为首版调试起点。

范围修订：64格仅用于停机坪周边采集；远程配送使用独立距离设置，建议初始1000格。配送不再要求目标箱位于采集圈内。

## 1. 玩法定位

新增“物流无人机停机坪”，内置一架专门搬运生产物资的无人机。玩家把多台自动采矿机、自动林场绑定到停机坪，再指定一个收货箱。无人机自动巡回取货、飞往箱子卸货、返回充电。

玩家能看到起飞、航行、悬停装货和落地；只有到达装卸点后才发生库存转移。搬运对象是设备现有产出格中的资源包，保持原物品数据，不自动拆包。

```mermaid
flowchart LR
    H[停机坪：调度与充电] --> S[采矿机 / 自动林场]
    S -->|收取已完成的资源包| D[无人机货舱]
    D -->|到达后卸货| B[玩家指定储物箱]
    B --> H
```

首版支持一个停机坪绑定多个来源、一个目标箱；用多个停机坪分别管理矿区和林场。普通随身无人机的跟随、治疗和背包功能维持独立。

典型布局：停机坪建在矿区或林场，收集周围64格内的设备产物，再送往数百格外的基地储物箱。采集范围决定“从哪些设备取货”，配送距离决定“能送到多远”，实际航程决定“耗时与耗电”。这三个数分别展示和校验。

## 2. 玩家操作

1. 在自动化设备制造工作台制作并放置停机坪，接入供电。
2. 长按停机坪选择“设置运输路线”，进入绑定模式。
3. 对准采矿机或林场长按交互，选择“加入取货列表”。远处储物箱可先就地“登记为物流收货点”，再在停机坪列表中选择；登记时验证玩家在箱子附近及访问权限，不要求跨越数百格时一直保持临时绑定模式。
4. 返回停机坪检查设备名称、坐标、权限、距离和航路；点击“保存并启动”。
5. 无人机开始巡回。收货箱无需放首格样品，未锁定的可用格都可以接收物品。

绑定采用明确点击，不自动把附近所有机器纳入运输。重复绑定同一设备合并为一条；来源超出采集半径、收货点超出配送距离、无权限和不支持的容器分别给出原因。取消、超时、死亡或退出会清除玩家的临时绑定模式；已登记收货点持久保存，使用时重新验证箱子实例和权限。登记不授予远程人工开箱能力。

停机坪面板：左侧是取货设备列表和优先级；中间是目标箱、航程和当前状态；右侧是货舱只读预览、电量，以及“启动／暂停派单”“召回”“取回滞留货物”。货舱仅在无人机停靠并取得库存编辑锁时允许人工取货。

## 3. 建议首版参数

| 项目 | 默认方案 |
| --- | --- |
| 无人机数量 | 每座停机坪1架 |
| 来源上限 | 8台，覆盖七种采矿机加一座林场 |
| 采集半径 | 仅来源设备须在停机坪中心64格三维半径内 |
| 配送距离 | 建议目标箱距停机坪最多1000格，可独立配置；不受64格采集圈限制 |
| 实际航程 | 停机坪→取货点→目标箱→停机坪的实际路径，包含升降与绕障；单独计算续航 |
| 载量 | 最多6个资源包；6格，每格最多1包，可混装 |
| 飞行速度 | 6格/真实秒，转弯和装卸阶段减速 |
| 装卸耗时 | 每处2真实秒，实际交付量以到达时可容纳数量为准 |
| 调度间隔 | 每2真实秒检查一次；缺料时降低检查频率 |
| 充电 | 建议满电提供600真实秒标准飞行时间，空电充满约60秒；按远程往返航程验证后调参 |
| 供电 | 兼容现有4格范围供电接口；具体电网负载在实现时验证 |
| 运行条件 | 服务器世界运行、所有者在线、当前阶段所需区块已就绪；沿途由受限的区块加载调度支持 |

每次先选一台来源，装入最多6包，送到目标后返航。首版不做途中多点拼单，便于诊断路线与货物归属。调度优先服务接近满仓的来源，同级按等待时间轮询，防止林场长期占用航班。

不设“必须满载才能起飞”。有1包也可配送；目标完全无空间时不派出空机。远端箱子预检查通过按需加载完成，缓存结果仅用于调度提示，不作为卸货凭证。当前设备通常储存18包，带资源打包器可存36包，对应至少3趟或6趟搬完，保留搬运吞吐量的意义。可选“满载优先＋最长等货时间”减少远程小批量航班，默认仍为有货即送。

电量按实际航行与悬停时间扣除，起飞前估算完整往返耗电，并保留满电容量的30%作为余量。范围内但绕障后超出续航时提示“路线超出续航”，不误报“超出采集范围”。1000格配送是独立距离建议，不能通过增大该参数绕过续航校验。游戏暂停和等待区块加载期间不耗电、不推进航班。

举例：停机坪周围40格的采矿机向800格外的箱子送货，直线往返约1600～1680格，按6格/秒约4.4～4.7分钟，另加装卸、升降和绕障。原120秒续航不适合这种远程用途，因此同步提高为600秒调试起点。距离上限按停机坪到目标箱的三维直线距离校验，不能把它写成整条航线长度上限。

## 4. 飞行、外观与状态

外观为工业四旋翼：深灰机架、黄色警示条、下挂封闭货箱、两侧起落架。空载时吊架收起，装货后显示货箱；旋翼、灯光和声音随距离降低更新频率。初步尺寸约1.2格宽，停机坪占地2×2格，顶部保留2格净空，最终以碰撞和镜头测试调整。

状态灯：蓝色待命、绿色运送、黄色充电或等待、红色故障。面板明确显示“取货点无产物”“箱子已满”“有人正在使用容器”“航路阻挡”“等待区块加载”“权限失效”等具体原因。

首版面向室外、开放式工厂。服务端规划“垂直起飞→巡航→下降”的折线路径，对整个机体做扫掠检测，不能只检测中心射线。允许有限次数抬高航线和局部绕行，不穿墙、不穿地、不自动开门。端点必须有可达的装卸净空，复杂室内迷宫不承诺可达。

远程航路分段规划和预取区块，前方区块未就绪时停在已验证的安全位置等待。规划使用逐段验证所得的航程估计，后续路径变长时持续检查剩余返航预算；不能按未加载地形视为空气，也不能在无人观察时跳过航行时间直接交付。

飞行途中检测新障碍；局部重规划失败时停止前进并尝试安全返航。返航也不可达则保留航班和货舱，显示“航路阻挡，等待处理”。召回同样必须走有效航路，不凭空把货物送回基地。

首版无人机作为停机坪管理的物流飞行表现，不承担战斗、载人和吸引仇恨功能，不接入随身无人机的部署数量限制。停机坪可以受损；战斗击落和维修玩法放在后续版本，避免首版同时引入尸体、货物掉落与实体回收链路。

## 5. 异常处理规则

| 情况 | 处理 |
| --- | --- |
| 来源无产物／正在打开 | 跳过本次，不改燃料、配件和生产进度 |
| 箱子在途中被塞满 | 能卸多少卸多少；剩余原样留在货舱，安全返航后等待重试 |
| 箱子被拆除、替换或权限撤销 | 暂停交付；保留货物，要求重新绑定，不自动改投其他箱子 |
| 取货前来源被拆除 | 取消该次取货，无货物生成 |
| 取货后来源被拆除 | 已进入货舱的货物继续送到原目标 |
| 容器被玩家或其他自动化设备修改 | 到达时重算容量与数量；预检查不当作最终承诺 |
| 停机坪断电 | 停止新派单；在途航班使用剩余电量完成安全返航，停靠后等待供电 |
| 玩家暂停或召回 | 停止新取货，在途机沿有效路径返回；已有货物保留供重试或人工取回 |
| 所有者离线 | 冻结任务和货舱、释放航班加载配额；恢复条件后重新验证，不计算离线飞行或补发货物 |
| 当前航段／装卸点区块未就绪 | 申请有限加载配额并等待；就绪后重新验证再推进，不访问未加载库存 |
| 已离开的来源／后方航段卸载 | 在库存事务已持久化且无需访问后允许释放，不因此冻结整趟远程航班 |
| 改来源／改目标 | 有活动任务时暂存新配置；旧任务完成或召回、清空货舱后才应用 |
| 拾取停机坪 | 必须停靠且货舱为空；否则说明原因 |
| 停机坪被摧毁 | 撤销派单，货物进入服务器持久化回收记录；以唯一回收ID生成一次原生掉落容器，区块未加载则延后处理 |
| 正常保存重启 | 恢复同一航班、货舱、电量和绑定；重新检查航路后继续 |
| 非正常崩溃 | 必须经事务恢复校验；不能判断时冻结相关任务，不盲目补发或删除物品 |

“物流数量守恒”包含来源、所有货舱、目标箱、玩家取回及掉落回收；生产新增和玩家消费另行计数。任何异常都不能把同一包同时计入两处。

## 6. 当前代码核对结果

以下是本地源码和配置事实，不代表运行时新功能已验证：

- 本设计来源白名单为 `AutoMinerIron`、`AutoMinerLead`、`AutoMinerCoal`、`AutoMinerNitrate`、`AutoMinerClay`、`AutoMinerShale`、`AutoMinerBrass`、`yfAutoForestry`。
- `98-AECxProjectZ_Tweaks/Config/items.xml` 定义 `yfForestryWoodBundle`，每包可拆出12000木头。直接搬包不触发拆包动作。
- `97-AutomationWorkshop/Source/InventoryTransfer.cs` 已有堆叠、数量、锁格及完整物品值保留逻辑，可提炼复用；现有函数一次转移一个槽位片段，不能直接等同于一次无人机航班。
- `Logistics.cs` 和 `Conveyors.cs` 有服务端调度、容器忙碌检查、所有权检查和区块写入互斥；当前路径受同区块限制。远程无人机需要新的跨区块设计，不能仅删除距离或 `SameChunk` 判断。
- `MachineSettings.cs` 可参考配置版本、玩家身份和8格交互距离校验；当前箱子筛选只接受特定自动化箱，普通储物箱需要新适配。
- 原生 `Data/Config/entityclasses.xml` 存在 `entityJunkDrone` / `EntityDrone`。配置证明原生无人机存在，尚不能证明其AI可直接用于多站物流。
- 自动化目录的源码、已安装版本与待装版本有差异；实现时需单独暂存完整包，明确集成基线，不从源码推断用户当前已运行同等功能。

## 7. 技术结构

建议在 `97-AutomationWorkshop` 内新增独立物流模块和方块ID `yfCargoDroneHub`，复用制造、供电和权限基础设施；采矿机与林场通过适配器读取，避免再次修改生产算法。新增数据具有独立格式版本，不给所有旧机器追加不兼容的库存特征。

| 模块 | 职责 |
| --- | --- |
| CargoDroneHub / 配置界面 | 停机坪、绑定、所有者、配置版本、充电、人工回收 |
| CargoDroneScheduler | 来源轮询、满仓优先、容量预检、航班唯一ID |
| CollectorSourceAdapter | 验证白名单、原生产物槽、访问锁；取货后调用经核实的原生更新接口 |
| StorageTargetAdapter | 适配玩家储物箱和自动化输出箱；尊重格锁、堆叠和访问权限 |
| CargoTransferService | 装卸计划、提交、库存版本和守恒检查 |
| CargoDroneFlight | 服务端路径、到达判定、续航和区块状态 |
| CargoDroneChunkScheduler | 端点按需加载、当前航段与前方小窗口预取、全服配额、排队与引用释放 |
| CargoDronePresentation | 客户端模型、插值、旋翼、货箱、灯光与声音 |
| CargoDronePersistence | 航班／货舱／回收记录、事务恢复和存档版本迁移 |

首版目标支持具备可靠物品库存与权限接口的玩家储物箱，以及 `yfAutoOutput`。不接入商人库存、玩家背包、车辆、世界战利品、其他机器的燃料或输入槽；未知第三方容器显示“不支持此容器”，不按方块名称猜接口。

权威货舱由服务器物流记录管理，客户端飞行模型不持有第二份库存。每次装货是“来源→货舱”，每次卸货是“货舱→目标”；服务器确认到达、容器可用且拥有有效权限后才提交。表现层丢失、重建或迟到加入不能产生货物。

持久化字段包括：世界标识、停机坪实例UUID、所有者、来源／目标实例标识与坐标、配置版本、DroneId、FlightId、阶段、位置／航点、电量、完整ItemStack货舱、事务编号、回收ID。运行时网络实体ID不作为重启后的唯一身份；原坐标放置新箱子不能自动继承旧绑定。

## 8. 库存提交与保存恢复：实现前必须验证

内存操作：服务器主线程计算装卸计划，对涉及容器按稳定顺序取得互斥，重验实例、权限、访问锁、格锁和数量；一次性提交两端变化并标记存档及网络更新，失败不得只写一端。原生生产、玩家开箱和现有传送带也必须与这些约束协调。

磁盘操作：跨区块保存与货舱记录可能分别落盘，内存互斥、`SetModified` 或原子替换单个XML文件都不足以保证崩溃后的货物守恒。

拟采用带唯一事务ID的预写日志、端点提交标记和恢复栅栏；标记必须与对应原生库存的保存版本一致。启动恢复期间先阻止涉及端点生产、人工访问和自动转移，再根据已保存版本进行幂等重做或回滚。不能只比较数量，也不能用旧库存快照覆盖重启后的新操作。

第一阶段需验证 `TileEntityCollector` 和普通储物箱能否安全携带版本标记，以及原生区块存读是否可建立协调保存边界；若不可行，重新选择保存机制并保留开发状态。仅增加外部事务日志不视为解决。掉落回收也需要同样的唯一性与崩溃恢复验证。

远程跨区块航班是正式首版目标；同区块原型仅用于验证接口。不能要求玩家提前加载完整千格航路，否则独立配送距离没有实际意义。方案改为按需加载端点与滚动航段窗口，不常驻整条航线或整个64格采集球。

加载范围由服务器统一预算；每架只保留当前安全航段、少量前方区块和当前操作端点，事务完成后释放不再需要的引用。停机坪监控所需引用计入预算；不能因模型不可见丢失停机坪销毁、断电等事件。没有配额或原生加载失败时排队等待，不能无上限增加区块。

原生服务器能否提供独立于玩家的区块加载／保持接口、分段路径查询，以及与世界存读和生产更新兼容，是实现前必须实测的第二项技术门槛。远端加载可能触发原生生产更新，需要验证其符合现有生产规则，不另行补发产物。如果接口无法满足，应重新讨论远程运输机制，不能静默退回“全程有人加载才运行”并宣称支持远程配送。

## 9. 联机与性能

配置请求只允许绑定位置、启停、优先级等玩家意图，不接受客户端上传的物品数量或“已到达”结果。服务端验证真实玩家、停机坪交互距离、收货点登记凭据、全部端点归属与明确访问授权、来源64格采集半径、独立配送距离和配置版本。远程绑定时玩家只需靠近当前交互端点，无需同时靠近停机坪和目标箱。首版设备必须同主人；给协作者管理权限不等于可向其私人箱子自动转货。

多个无人机争抢来源时，调度预留短期取货任务，到达时仍重验剩余产物；预留超时释放。目标容量预检只影响派单，不占用玩家槽位。任一实际装卸点正在被访问时等待或跳过，不能覆盖玩家操作。

服务端同步 DroneId、FlightId、阶段、航点、位置与时间戳；客户端插值，建议初始每秒2～5次位置更新，关键状态变化即时推送。专用服务器不加载材质和模型；迟到加入先接收完整快照。

只维护已登记端点，不每帧扫描64格球体，更不扫描1000格配送范围寻找箱子。调度分帧限额、路径结果缓存，环境改变或障碍检测失败才重规划；容器忙碌或缺料采用退避重试。加载配额上限根据多停机坪、远程航路和服务器内存压测确定。

## 10. 开发顺序与验收

1. 接口原型：真实采矿机／林场→货舱→真实箱子，验证燃料和生产计时不变、产物取走后继续生产、格锁及打开容器保护。
2. 持久化与远程加载原型：完成跨区块、不同保存顺序和强制中止恢复实验；验证无玩家陪同的远程航路按需加载和释放，确定事务方案及服务器区块预算。
3. 完整玩法：停机坪、明确绑定、状态界面、充电、来源轮询、暂停召回和滞留货物取回。
4. 飞行表现：服务端航路与到达判定，客户端工业无人机、装卸动画和联机插值。
5. 联机验收：独立服务器、两个图形客户端、迟到加入、断线重连及至少16座停机坪同时运转。

验收最低要求：

- 七种采矿机与林场均只取已完成产物，包数量和物品元数据一致；不移动燃料或配件，不重置生产计时。
- 目标空箱、部分空位、混合物品、全满、锁格、双人开箱与传送带同时写入时数量守恒。
- 多无人机同源、来源补货、取货瞬间拆机、目标原位重建均不重复取货或误投。
- 装卸前后、日志写入和每个端点保存之间强制终止，再启动验证数量与事务ID；覆盖跨区块保存顺序变化。
- 新建障碍、复杂林场模型、屋顶、边界区块卸载、返航失败和失电场景无穿墙交付。
- 64格边界内来源可绑定、边界外来源拒绝；800格外指定箱子可配送，配送上限外目标单独报错，绕障增加航程只影响续航校验。
- 无玩家沿路跟随时，远端装卸和往返仍能完成；全程不要求所有航段同时加载。达到加载配额时等待、结束后释放，多停机坪不持续扩大区块驻留。
- 正常重启、断线、停机坪销毁和掉落回收不产生第二份货物；异常无法恢复时可定位被冻结事务。
- 双客户端所见航班和库存一致，客户端伪造航班／配置／位置不能改变库存。

编译、离线库存测试和无界面测试分别记录；图形航路、动画及双客户端体验必须在真实游戏中另行验收。本次交付仅为设计文件，以上均为后续验收要求。
