# 1.0.4 大屏修复验证（2026-09-28）

## 输入与证据

用户截图显示全白屏体、原生“(E)关灯”提示及错误放置效果。当前客户端日志确认加载的是 1.0.3。

读取本机 3.2 b10 的 Assembly-CSharp.dll 后确认：

- `BlockPoweredLight` 默认命令为 `light`，提示由灯具生成；旧代码只在命令列表末尾追加设置，未实现直接激活重载。
- `ceilingLight01_player` 继承 `lightPorchWhite` 的 TintColor/Light 等属性。`BlockShapeModelEntity` 激活/预览时会覆盖模型 `_Color`。旧屏体使用白色纹理，依赖材质颜色变暗，存在被原生着色覆盖的问题；本次移除灯具继承并将暗色编码到纹理。由于未做图形复现，不能将白屏全部归因于单个因素。
- 原生偶数宽度模型会额外向 X 偏移 -0.5；模型根的 Y 为方块底面。本次用 ModelOffset.x=0.5 抵消前者，屏体中心 Y=1.5，覆盖底排到顶排 3 格；根碰撞体让原生模型池得到屏体实际边界。
- 原有 `TowardsPlacerInverted` 的自动方向取玩家与命中点的水平位置差。新 helper 在自动/对面模式直接选择墙面法线对应的直立方向，保留手动方向。

## 已完成

1. 原 1.0.3 DLL 备份：`.local-tests/Surveillance/pre-screen-fix-1.0.3/PZAEC.Surveillance.dll`。
2. `pwsh -File tools/Surveillance/Build.ps1`：通过，直接引用安装游戏的程序集，输出 mod 根 DLL。
3. `pwsh -File tools/Surveillance/Test.ps1`：通过。
   - 调度、帧龄、画质策略；红框类型/投影；保存、权限、版本及网络序列化。
   - 新增生产屏幕类/放置 helper 的 API 替身测试：首命令设置、直接激活、子格解析、开关、原生拾取路由及供电 Tile 类型兼容。
   - 四墙面的自动/对面朝向、保持直立、屏体八角均位于旋转后的 12 格占位内、背板距墙 1 厘米、手动旋转不被覆盖。
   - 独立屏幕 XML 不继承灯具，不带 TintColor/Light/RuntimeSwitch，原点补偿匹配。

## 待游戏内验收

用户选择暂不退出正在运行的游戏，本次未启动隔离原生 QA，也未重载用户存档。离线测试的 API 替身不能验证 GPU 着色、实际鼠标/手柄输入或原生放置选择器。

重启服务器与客户端后：

1. 确认日志 `Loaded Mod: PZAEC_Surveillance (1.0.4)`，并查看 `[Surveillance] Monitor shader=...`。
2. 先看旧屏体应为暗色；无电时短按 E 仍可打开设置，点击按钮时不挥动工具，Esc 后恢复操作。
3. 对四个方向的完整墙面放置新屏：选择自动模式，背面贴墙，正面朝玩家。留足墙前 4×3×1 空位；验证中间、四角均可交互。
4. 接电、开启屏幕、绑定摄像头后查看动态画面；切换频道、断电重连、红框开关及共享同一摄像头的两块屏幕。
5. 旧屏方向不对时拾取重放；新放置是新设备，重新检查频道绑定。
