# 四路优化 1.0.2 验证记录

日期：2026-09-28。

## 已交付

- 玩家主相机视锥、屏面正面、8/10格距离回差和200ms离开视野宽限。
- 稳定摄像头身份的到期调度，每帧最多一次绘制；每帧最多创建一个新相机。
- 1～2路10Hz目标，3～4路焦点10Hz/其他5Hz，无焦点各6Hz。
- 768×576、512×384、384×288投影尺寸分档；15%阈值回差、升档300ms/降档1s、两秒重建冷却。
- 首帧成功才展示；300ms提示延迟、500ms撤下旧帧；失败重试100/250/500ms、日志限频。
- 同镜头共享最高可见画质；最多四路活动及四路闲置缓存，五秒闲置释放。
- 复用工作集合、缓存GUID索引及文字/材质状态；共享纹理换帧后才释放旧纹理。
- 远端状态快照超过六秒提示同步中断。
- 可选本机自动保底，默认关闭：两秒压力降档、十秒稳定恢复，目标频率最低5Hz。
- 可选诊断和CSV导出；分析脚本Measure-Recording.ps1。

## 已执行的验证

1. 使用本机游戏程序集编译DLL通过。
2. Test.ps1及Test-Policy.ps1通过。直接编译实际RenderPolicy.cs进行30秒虚拟时间行为测试；覆盖到期队列、不同刷新目标、公平性、失败退避、快速换频道不饿死其他路、无效/过期帧、观看回差、纹理档位回差与冷却。
3. 调度模拟结果（成功更新数；不包含真实场景绘制成本）：

| 游戏帧率 | 分配 | 四路30秒更新数 |
| --- | --- | --- |
| 60 FPS | 10/5/5/5Hz目标 | 288 / 148 / 147 / 147 |
| 30 FPS | 10/5/5/5Hz目标 | 263 / 142 / 141 / 141 |
| 30 FPS | 各6Hz目标 | 167 / 167 / 167 / 166 |
| 15 FPS | 各6Hz目标 | 113 / 113 / 112 / 112 |

实际更新率低于目标是逐游戏帧调度且不补帧的结果，不把目标值当作实测Hz。15 FPS场景用于确认有序降速和不饿死，并未满足四路各5Hz。

4. 诊断分析脚本通过已知样本核对：16/20ms帧时间得到均值18ms、p95为20ms；两次间隔200ms的绘制得到5Hz；首帧样本30ms被正确统计。
5. 原生隔离专用服务器启动通过：日志`.local-tests/Surveillance/NativeSmoke/run-eefd1792ca3d4aedbee4afb3ef039e35/game.log`确认1.0.2初始化、XML加载、12格足迹及供电设备注册器。该启动检查不执行客户端观察和绘制。

## 尚未取得的证据

未取得真实玩家客户端的四路画面、地下室门口场景、GPU帧时间、实际显示延迟及多客户端画面证据。因此不能声称已达到平均帧时间增加≤15%、p95增加≤20%，或主看200ms/其他300ms的实际呈现延迟指标。

自动保底作为试验功能默认关闭；阴影/后处理裁减、墙体遮挡硬停播暂不启用。启用这些需要独立的场景真实性验收。

## 客户端验收操作

1. 重启并加载相同基地，放置四块屏幕分别绑定四个摄像头。摄像头取景涵盖可移动目标及一扇门。
2. 开启菜单中的“记录性能”，关闭菜单；预热30秒后测试正面观看、背对再转身、快速换频道和夜间，每组60秒、至少三组。测试前后保持游戏画质和站位一致。
3. 点击“导出记录”，从日志获取events.csv路径，执行：

```powershell
pwsh -File tools/Surveillance/Measure-Recording.ps1 -EventsPath '完整路径/render-日期时间.events.csv'
```

4. 对比无绘制与四路观看的游戏帧时间，检查各路更新间隔、首帧等待及资源上限。事件0记录游戏帧时间；事件1/2记录成功/失败绘制。采样和CPU数据不能代替GPU和屏面实际呈现时间。
5. 用受控开关门或可视测试标记配合录屏，验证本地场景变化到大屏显示的时间；联机另测网络影响。诊断事件缓冲超过65536条时只保留最新部分，头部标记被覆盖数，长测试应分段导出。
6. 四路性能达标后再开启“自动保底（试验）”测试重负载降档和恢复。出现持续低帧率时应清楚显示延迟，不接受冻结画面仍被当作实时。
