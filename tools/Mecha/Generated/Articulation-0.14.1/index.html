采集 5,433 条原生姿态记录，覆盖 121 个场景标签（包含视角、方向和衔接变体，并非 121 套独立动画）。包括站立、行走与转向、上下机、举盾、蓄力、普攻、重劈及连招、跳跃落地、飞行起降/加速/转弯/失去动力，以及上台阶、下台阶和跨沟。挑选 42 个代表/极端姿态，每个生成 5 个原生视图。

去贴图后的原生证据

颜色仅区分骨骼归属，不是游戏新皮肤。使用实际模型、原生 BakeMesh 和测得的姿态矩阵复现；抽样顶点复现误差小于 0.001 m。图片点击可放大。中央舱口属于主动开舱，不计作破洞。

问题原因与整改顺序

  1. 先修肩肘腕、髋膝踝的分件边界。当前从整体雕塑按空间和骨骼归属分配三角面，运动后会把原本相邻的表面分开。需按机械结构重分件，排查跨部件归属，不能只缩小动作幅度。
  2. 给活动交界补真实连接结构。补封口、内衬与关节轴套/球体，让外甲在允许角度内仍有承接。已有膝轴芯只覆盖有限区域。
  3. 再调整机械活动限位和装甲避让。分件修复后复跑同一姿态集，重点复查高抬腿、最大屈肘、持盾和展开翼根。
  4. 最后才签署无明显破损。必须同时满足原生外观复核、接缝遮盖及相邻装甲碰撞检查；动作、伤害和网络回归通过不能替代这些条件。

测量口径

接缝审计追踪原姿态中重合、后来分配到不同骨骼的顶点。其分离距离用于寻找最需要复核的帧，不是实际空洞宽度：关节转动、原始融合重叠和舱门开启都可能产生较大距离。自动审计状态是 REVIEW REQUIRED，不伪装为通过。功能测试显示 PASS 的部分仅表示各自断言成立。

未签署所有装甲之间的精确体积无碰撞、真实双机联网或真人驾驶光照验收。当前模型已有明确外观缺陷，足以判定整体验收未通过。Test-Complete.py 的源模型、刚性绑定与翼片检查通过，但其历史试验体配置快照断言仍失败；它对比旧版本 vehicles.xml，与本次未改动的现行驾驶配置存在差异。
