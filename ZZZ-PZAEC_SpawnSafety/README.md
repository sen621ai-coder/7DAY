# 地基下刷怪防护 1.2.0

适用当前安装的 7 Days to Die V3.2、AEC 与 T16–T19 扩展。DLL 已编译到本目录，下一次启动游戏/服务器加载，无需重开存档。

## 1.2.0 独立生成延后兜底

- AEC 倍率额外怪、击杀替补和热度护卫若已创建实体但原落点与 8–64 米外围全部无效，记录一次待补生成。6 秒后重试，再失败则分别延后 12 秒和 18 秒；每条最多重试 3 次、队列最多 32 条、每帧最多处理 2 条。
- 每次延后重试都重新调用 AEC 直接生成入口，先检查原点，再在 8–96 米内寻找合法落点。实际生成成功才记录 recovered；失败会记录 retry-pending、exhausted、unloaded-pending 或 unloaded-exhausted。暂时未加载的区块也会占用一次重试次数。重试沿用 AEC 的商人距离限制和 SpawnSafety 的地基、屋顶、净空检查。倍率额外怪与击杀替补重试时保留 AEC 的递归抑制状态。
- 事件首领、血月、随从和有任务/波次归属的生成仍交给原有管理者，避免脱离原流程补出一只未计数的怪。队列只存在于当前游戏世界的内存中；换世界或重启会清空。即使延后重试，封死、未加载或不满足原生保护规则的地点仍可能最终失败。

## 1.1.1 诊断补充

- 记录 AEC 直接刷怪在实体入世前返回失败的次数与原因，包括商人 80 米限制、预算耗尽和创建失败。随从最终失败另记汇总。
- 记录血月和 PZAEC 地表事件的初始选点失败后，外围搜索成功或耗尽；若实体根本没创建，也会有 `selector-failed` 记录。
- 记录 AEC 领地石检查命中次数（包括选怪阶段）；排除半径由 AEC 设置控制，当前配置为 50 米。
- 各类结果首两次立即输出，此后每分钟输出累计次数；即使一分钟内没有新尝试，也会补写累计数。SpawnSafety 的判定逻辑没有变；AEC 领地石半径另改为 50 米。

## 本次修正：减少基地周围的刷怪损失

1.0.1 中部分直接入口只校验原坐标，随从也只能在很小的范围内重试，失败可能丢掉本次生成机会。1.1.0 先尝试原有选点，再分段向外围寻找合法地面；血月和自定义事件在创建实体前选点失败时也可以进入这层兜底。尚未取得实战日志来量化此前减量比例。

同步搜索找到位置后仍使用同一个待生成实体，并走原来的入世、ID 捕获、随从归属、任务/波次计数流程。1.2.0 仅给上述三类无任务归属的独立生成加入有界延后队列，没有提高刷怪倍率。

## 选点与边界

| 检查 | 当前规则 |
|---|---|
| 区块 | 中心与身体四角所在区块均须已加载 |
| 支撑 | 向下射线找真实支撑面，最多下降 3.5 米；检查脚底四点，高差不超过 0.65 米；脚底置于最高面上方 0.08 米 |
| 净空 | 按实际宽、高检查；建筑用方块形状碰撞盒，地形用真实碰撞面，考虑浮动原点 |
| 地表 | 排除明显低于自然地面、比自然地面高 2.5 米以上的平台，以及正上方结构遮盖的位置 |
| 建筑附近 | 取消“相邻三列遮盖也拒绝”的规则，允许建筑旁有净空的露天地面；忽略树模型的遮盖 |
| 原范围尝试 | 有原选点器时最多 12 次；随从外层尝试共享预算 |
| 外围兜底 | 最多 16 次原版选点器调用，分四段、每段四次，原范围失败后向外找；创建实体前后共享这份外围预算 |

单次原版选点器内部仍有原有的有限循环，因此“16 次”指选点器调用次数，不是世界方块查询次数。外围落点同样经过支撑、体型、地表和头顶遮盖检查，不会为了凑数把怪硬塞进地基或抬到屋顶。

## 各入口兜底范围

| 入口 | 范围与失败处理 |
|---|---|
| AEC 随从 | 原小范围失败后，以首领位置为中心找 8–64 米外围；全部失败才交回原 PendingFollowersByKey 队列 |
| 其他 AEC 直接生成、击杀替补、倍率额外怪、幽灵/热度护卫、Nemesis 等 | 先用原坐标/选点器，失败后以原请求落点为中心找 8–64 米外围；每个实体独立预算。其中倍率额外怪、击杀替补、热度护卫在实体落点全部失败后还可延后重试，延后范围 8–96 米 |
| MegaHorde | 原 X/Z 各 ±12 米选点失败后，以原落点为中心查 8–64 米外围；只计入真正成功的实体 |
| 血月 | 以原关注点为中心，下限 max(30, 原半径−10)，上限 max(64, 原半径+32)；保留至少距玩家 30 米及原版睡袋策略；全部失败才返回原失败分支 |
| PZAEC 地表事件 | 保留原最小距离（至少 8 米），兜底上限通常为 64–96 米；全部失败仍保留事件待生成条目和原超时规则 |

常规外围四段为 8–22、22–36、36–50、50–64 米；距玩家至少 12 米并检查睡袋。AEC 直接入口继续执行距商人 80 米的原限制。事件 safe_spawn=false 时还会检查外围落点的建造保护权限。

使用原版 GetMobRandomSpawnPosWithWater 获取坐标和原生约束，不额外套用不同的取整/水域检查。初次选点失败也能进入兜底；实体创建后关闭这层初始选点补救，避免入世回调中的其他刷怪误用外层参数。

保留原版 POI 休眠怪和普通事件；地下事件不使用地表扩圈。EntityFlying、事件 airSpawn、玩家、非敌对实体和 aec spawn 调试命令保留原有行为；凤凰独立空中入口未改动。非敌对及飞行事件在创建实体前也会排除。

## 失败、诊断和性能

- 原范围及外围全部找不到合法位置时，仍如实返回失败。有原队列的入口继续原有重试；上述三类独立生成在本次调用返回失败后进入限量延后队列，其余无队列技能仍可能少生成本次怪物，不能保证任何建筑布局都能补齐。
- 不挂接全局 World.SpawnEntityInWorld，不改写其他模组全部入口、原版生物群落刷新或存档加载。已存在的怪物不被传送、杀死或删除。
- 只有尚未入世的失败预制体会被停用和释放；不调用死亡、经验、掉落流程。
- 日志前缀 [SpawnSafety]。外围救回的生成带 perimeter-fallback，实体落点全部失败带 rejected；创建前失败带 selector-failed 或 failed。延后队列带 deferred:queued、retry-pending、recovered、exhausted、unloaded-pending、unloaded-exhausted 或 queue-full。包含来源、怪物类型、原落点和最终落点。
- 同类结果先记录两次，此后每 60 秒汇总一次累计次数，不发送聊天提示。
- 最多观察 128 个新实体，每帧最多检查 8 个，约 1 秒、3 秒时记录异常下落，不干预已有实体。
- 遮盖只查中心列至当前实际方块高度，不扫描空天空；每次实体生成重新读取建筑状态。
- 入口签名不兼容会回滚本模块全部挂钩并记录 NOT ACTIVE。

## 验证与游戏内验收

构建：tools/SpawnSafety/Build.ps1。完整离线回归：tools/SpawnSafety/Test-All.ps1，五组测试分别在独立 PowerShell 进程执行。

当前通过 86 项规则/恢复流程检查、16 项 Sites 适配层模拟检查、5 项诊断累计/汇总检查、48 项延后队列检查、267 项真实 DLL 签名、分支、作用域及补丁组合检查。覆盖：大片地基外移成功、同一实体只接受一次、外围次数上限、初始选点失败及诊断、睡袋/商人/建造保护、地下不扩圈、延后队列成功/耗尽/容量/区块暂时卸载/换世界清空、整个外围封死时如实失败。保留与现有 T16–T19 血月补丁的两种组合顺序验证。

以上使用合成世界、模拟原生物理、真实 DLL 指令审计和隔离分支执行，不等同于实际 Unity/Mono 波次实测。

游戏内优先验证：启动日志有 1.2.0 loaded；在同一基地观察外围随从、热度怪和血月数量，以及守点波次推进。查看 claim-check hit、failed、selector-failed、perimeter-fallback、rejected 和 deferred 的累计次数；检查地基内没有新怪、波次/任务只计入真正生成的怪物。若基地及其外围超过搜索上限均被封死，仍应出现明确失败记录，而非强制刷入建筑。
