# 地基下刷怪防护 1.0.1

适用当前安装的 7 Days to Die V3.2、AEC 与 T16–T19 扩展。按“诊断与随从 → 血月 → 自定义事件和技能”完成接入。DLL 已编译到本目录，下一次启动游戏/服务器加载；无需重开存档。

## 判定规则

在实体预制体创建完成、加入世界之前，读取实际碰撞尺寸检查候选位置。尺寸未初始化时采用保守的缩放尺寸兜底。

| 检查 | 当前规则 |
|---|---|
| 区块 | 中心与身体四角所在区块均须已加载 |
| 落脚点 | 向下射线找真实支撑面，最多下降 3.5 米，不向上搜索屋顶 |
| 支撑 | 检查中心和四个脚底采样点，高差不超过 0.65 米；脚底置于最高采样面上方 0.08 米 |
| 净空 | 按实际宽、高检查；建筑用方块形状碰撞盒，地形用真实地形碰撞面，考虑浮动原点 |
| 地表入口 | 排除明显低于自然地面的点、比自然地面高 2.5 米以上的平台，以及头顶结构遮盖的点 |
| 遮盖 | 中心上方有宽、深均不小于 0.6 米的实体结构即拒绝；周围四列中三列遮盖也拒绝；忽略树模型 |
| 重试 | 有可靠原始选点规则的入口，每个实体最多校验 12 个候选点；随从四轮外层尝试共用这 12 次预算 |
| 保护区 | 保留原有选点器的限制；AEC 直接生成入口及其重新选点均保留距商人 80 米检查 |

这是一组保守规则：狭窄通道、陡坡、桥下和建筑遮盖处可能被地表入口舍弃。不会为了找到位置而扩大既有刷怪半径，也不会把地基下的怪抬到屋顶。

## 覆盖与失败处理

| 入口 | 选点和失败行为 |
|---|---|
| AEC 首领随从 | 调用现有随从选点器，失败返回 `false`，原有 `PendingFollowersByKey` 队列保留待生成项；成功输出实际落点 |
| 原版血月队伍入口 | 使用原来的 `CalcSpawnPos` 重新选点，失败在入世及成功计数前返回 `false`，后续重试由血月队伍控制 |
| PZAEC 自定义事件 | 仅 `PZAEC…` / `eventPZAEC…` 序列；使用原来的 `FindValidPosition` 和原半径、偏移、保护区参数；返回 `null` 时事件保留待生成项，原有超时规则不变 |
| MegaHorde 技能 | 保留原点周围 X/Z 各 ±12 米的范围，原地面高度选取；失败走原来的空实体分支，只计入实际成功数量 |
| 击杀替补 | 保留原半径 8–24 米和地表高度选点 |
| 热度护卫、幽灵击杀召唤 | 保留原半径 5–13 米和地表高度选点 |
| 刷怪倍率额外怪 | 保留原半径 1.5–3.5 米、来源实体高度附近选点 |
| 其他 AEC 直接生成（含事件首领、复仇/Nemesis 等） | 校验调用方指定坐标，不猜测它的合法搜索范围；无合法落点则报告失败，保留调用方原有重试、冷却逻辑 |

技能并非都有持久补刷队列。无队列的技能在所有候选点失败后会少生成本次怪物；不会伪报成功，也不会凭空创建无限补刷队列。任务待生成列表、血月与随从的失败处理分别沿用已经核对的原有机制。

保留原版 POI 休眠怪和普通原版事件；自定义事件若锚点位于地下，只校验支撑与身体净空，不套用地表露天要求。所有 EntityFlying（含秃鹫）、事件 `airSpawn`、玩家和非敌对实体跳过地面规则；`aec spawn` 调试命令保留手动生成行为。凤凰独立空中生成入口未改动。

未挂接全局 `World.SpawnEntityInWorld`，不会全面改写其他模组、原版生物群落刷新和存档实体加载。已存在的怪物不会被传送、杀死或删除。本模块只销毁尚未注册到世界的不合格预制体，不调用死亡、经验、掉落或尸体流程。

## 诊断与性能界限

- 日志前缀 `[SpawnSafety]`，包含来源、怪物类型、原落点、调整后落点或拒绝原因。
- 每种来源/结果先记录两次，以后最多每 60 秒记录一次，并带累计次数；不发送聊天提示。
- 最多观察 128 个新生成实体，每帧最多检查 8 个，在约 1 秒和 3 秒时观察异常下落/低于地表，只记录，不干预。
- 无全地图扫描、无全体怪物遍历；头顶遮盖只扫描中心和周围四列至该列当前实际方块高度（最多至世界高度上限），不扫描空天空，扫描结果仅在一次实体选点中缓存，下一次生成可看到建筑改变。
- 挂钩无法匹配当前版本时，回滚本模块挂钩并输出 `NOT ACTIVE`，不会留下半套挂钩。

## 验证

编译与离线验证脚本：

```powershell
& tools/SpawnSafety/Build.ps1
& tools/SpawnSafety/Test-All.ps1
```

复核后结果：70 项规则/运行逻辑检查、16 项实际 Sites 适配层模拟检查、211 项真实安装 DLL 的签名、指令分支、作用域及补丁组合检查通过。包括与现有 T16–T19 血月选怪补丁的两种应用顺序，以及随从失败进入原有待生成队列的分支。测试使用合成世界验证地形规则，用 Cecil 检查游戏实际 IL，并在隔离动态方法中执行注入的成功/失败分支；不等同于已完成 Unity/Mono 游戏内验收。

游戏内验收顺序：

1. 启动日志应有各入口 `hook ready`，最后有 `1.0.1 loaded`，没有 `NOT ACTIVE`。
2. 大片实心地基、带空腔地基、架空平台旁触发随从。检查其生成在合法地面，封死区域不会硬塞；留出口后原有队列可继续生成。
3. 在同样建筑旁测试血月；检查波次继续推进、击杀与掉落正常，日志出现拒绝/重新选点时没有成功计数虚增。
4. 测试守点/试炼/追猎以及技能召唤；检查守点待生成条目不因空位置提前消失。
5. 对照平地、缓坡、地形跨区块、大体型 T19 怪物、合法地下 POI、空中敌人；重点观察大型怪净空和地形碰撞。
6. 若还有地基下怪物，结合来源日志和 `post-spawn-fall` 判断是未覆盖入口、初始位置遗漏，还是生成后移动/掉落。后者本版本仅诊断。

当前尚未进行上述游戏内实测，因此不能保证所有入口或所有地基结构都已杜绝地下怪。
