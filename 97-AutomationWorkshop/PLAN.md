# 自动化工厂实施计划

## 目标与当前版本
在七日杀 V3.2 整合包中建立可联机使用的工厂系统：自动采矿、运输分拣、农场和食物生产、装备分解、冶炼锻造、炮塔补弹。使用独立 Mod `97-AutomationWorkshop`，设备统一由自动化工作台制造。

当前 0.4.0 已实现制造入口、分拣与箱间输送、自动厨房、冶炼、锻造、装备分解、成熟作物收割补种和矿点持续采集。新增水泵、储水箱、灌溉作业加速与炮塔外接弹仓。通过1925项离线检查；游戏内验收、可见输送带和高级设置仍待完成。

## 阶段一：制造入口（已实现，待游戏内验收）
- [x] 原生 Workstation 方块、独立配方范围、原生队列与输出槽。
- [x] 在普通工作台制作自动化工作台，配方明确且无额外技能门槛。
- [x] 自动化机架、电机、控制器、水泵、切削和输送组件共六类零件。
- [x] 中文名称与说明、独立原生窗口组，复用原版模型。
- [ ] 两台客户端验证摆放、交互、排队制造、取出产物和重启后队列。

## 阶段二：物流与机器运行基础（基础版本已实现，扩展设置和实机验收待完成）
- [x] 输入/输出箱、分拣机、10W供电接口及制造配方。
- [x] 服务端转移、样品过滤、距离优先、所有权和容器编辑锁检查。
- [x] 同区块保存、原生物品数据复制、1822项独立库存回归。
- [ ] 库存目标、分类规则及手动优先级界面。
- [ ] 双客户端操作、通电、读档和强制终止恢复的实机验收。
- 输入箱、输出箱、控制器、分拣机；第一版相邻容器或短距离连接。
- 服务端统一执行物品转移；客户端只提交配置操作。验证拥有者和队伍权限。
- 按物品、分类、目标库存和优先级过滤；满仓、缺料、断电明确停机。
- 不覆盖箱内物品，不把耐久、品质、模组和自定义数据丢掉。
- 为重复请求、双人同时取物、拆机、掉线、存档恢复建立回归测试。
- 首版区域卸载时暂停，不提供离线补产；限制每次更新转移数量。
- 验收：输入 100 个材料，输出、在途与剩余合计严格等于 100；重连和队列满不会重复搬运。

## 阶段三：采矿、农业、食品
- 采矿机：先验证矿点并定时消耗能量与钻头产出；真实挖掘和地形变化作为后续独立功能，不默认破坏地形。
- 农场控制器：扫描限定范围耕地，使用真实种子，成熟后收割，留种补种。
- 水泵与水箱：供水、储量和不足提示；灌溉增益按实际作物机制适配。
- 自动厨房：固定食谱、库存目标、取料/烹饪/输出；复用整合包食物配方。
- 验收：不隔墙越权收邻居作物、不收未成熟作物；产出与输入、留种数量可核对。

## 阶段四：装备分解与锻造
- 战利品输入 → 过滤 → 可选拆模组 → 分解 → 材料分类。
- 默认保护传奇装备和带模组装备；质量、耐久、装备类型、白名单独立配置。
- 先验证整合包已有回收台和配方，不能靠物品名称猜材料产出。
- 矿石输入 → 冶炼 → 金属库存 → 锻造配方 → 成品输出。
- 复用实际熔炼倍率、燃料与配方，不把同一份材料同时记入炉内和箱子。
- 验收：保护规则可靠、拆卸保留模组数据、掉线不重复加工、输入不足不产出。

## 阶段五：可见运输和防御整合
- 直线/转角/升降输送带、分流器、装卸口；服务器计算物品状态，客户端显示运输动画。
- 炮塔沿用原生敌我识别和射击；供弹器识别正确弹种，遵循容器与炮塔权限。
- 设备耗电、状态面板、运行声效、堵塞提示，后续再做自定义模型。
- 验收：双客户端观察一致、血月大规模设备压力测试、路径断开和拆机后物品守恒。

## 默认设计
- 自动化工作台本身是原生装配台；自动机器的供电和运行由第二阶段实现。
- 核心流程先实现，再增加动画；不创建大量真实掉落物模拟传送带。
- 初版不跨未加载区运行，不补发离线产物。
- 新机器逐台开放制造配方，通过运行验收才作为可用设备发布。
- 不改既有存档地形、不替换原工作台、不更改其他 Mod 的生产配方。
