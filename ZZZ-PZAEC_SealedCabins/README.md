# 密闭座舱环境防护 1.0.0

适配当前 V3.2 / Project Z / AEC 整合。M1（T16–T19）、MD-500 和阿帕奇共用同一套防护；所有实际乘坐的驾驶员、炮手及乘客均有效。仅在仍有耐久、未死亡的载具内生效，停车、熄火、缺油不影响环境隔绝。站在旁边、站在车顶、其他载具均不生效。

## 实际规则

- 阻止炎热、酷热、寒冷、冰冻与指定环境辐射 Buff 的新增。已有的即时环境状态在下一次玩家状态更新时移除；对应被动惩罚和伤害实时检查座舱状态。
- Project Z 的即时热暴露 `$HotStatus`、冷暴露 `$ColdStatus`、活跃辐射暴露 `$ActiveRadiationStatus` 在舱内按零处理，阻止暴露引起的持续累积。冷、热和辐射环境不额外消耗玩家生命、水分或食物。
- **不清零累计辐射 `$IRradiationStatus`、中暑 `$ThermoplegiaStatus` 或冻伤 `$FrostbiteStatus`。** 原有治疗和恢复逻辑继续运行；已有辐射病不是上车即治愈，其自身负面效果仍可能存在。中暑、冻伤按脱离恶劣环境后的原规则逐渐恢复。
- 沙漠、雪地、废土危害的直接扣血、痛呼、危害粒子与暴露倒计时一并处理。原版风暴及其 Stage/Recover Buff 已被当前 AEC 全局删除，本模块不恢复它们。
- 不赋予地图、生物群系任务完成状态，不伪造全局室内/庇护判定。不处理感染、流血、骨折、燃烧、窒息、饥渴等其他状态。
- 保留怪物直击的原有伤害与 `SmallMiniBossHitRad` / `MiniBossHitRad` / `BossHitRad` 辐射效果，以及药物反作用。这里的辐射隔绝针对环境/持续暴露入口，不能视为所有攻击免疫。
- 下车、载具摧毁、玩家死亡或换乘其他载具后，实时判定立即失效；环境 Buff 和暴露数值在原生下一次更新重新计算。没有保存或延时残留的免疫 Buff。

## 安装

本目录与三个载具模组并列安装；依赖已安装的 `0_TFP_Harmony`、当前 Project Z/AEC 配置。不要只复制 DLL，`Config/buffs.xml` 也是防护的一部分。服务器和客户端需同时安装相同版本，完整重启游戏/服务器后生效。

当前 MD-500 原始 Buff 只提供载具自损修正，阿帕奇没有环境防护，M1 原有乘员保护只阻止车体受伤连带扣血。新增本模块后统一隔绝，不改三者飞控、武器、装甲或储物规则。

## 实现与验证

`Source/CabinProtection.cs` 精确匹配六个载具 ID，按玩家实时 `AttachedToEntity` 与载具生命状态判断。原生 `EntityBuffs.AddBuff` 核心入口阻止指定暴露 Buff；XML 使用带程序集名的自定义条件限制当前整合中的具体环境效果。没有每帧全图扫描、玩家附近防护光环或新网络包。

执行 `tools/SealedCabins/Test-All.ps1`：实际防护方法通过模拟游戏对象验证，合并本机全部 Buff XML 后验证补丁位置、恢复行为、疾病和药物规则不变，再按已安装游戏程序集编译 DLL。离线测试不等于游戏内实测。

实机验收：

1. 三种载具分别测试驾驶席和其他可用座位，包含熄火与空油。
2. 在沙漠、雪地、废土停留，上下车对比冷热、活跃辐射和危害扣血。
3. 带已有累计辐射/中暑/冻伤上车，确认不瞬间清零，保留原有治疗与逐步恢复。
4. 测试步行靠近、车顶、换乘其他载具、载具摧毁、死亡复活及保存重载，确认无遗留免疫。
5. 专用服务器双人同乘与客户端重新连接；测试怪物直击、感染/流血和药物反作用仍按原规则生效。

本版本尚未完成以上客户端/专用服务器实机验收。
